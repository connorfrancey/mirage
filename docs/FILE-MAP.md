# File map

One line per header: what the file is, taken from its leading comment. Generated by `python tools/file_map.py`;
read the header itself for the details. See [AI-GUIDE.md](AI-GUIDE.md.old) first.

## loader/include/mirage

- `loader/include/mirage/api.h`: Mirage mod API, ABI version 1 (Mirage step 4). The one header a native mod needs.
- `loader/include/mirage/imgui.hpp`: The menu's ImGui in a native mod built against the same ImGui version (MirageApi::imgui_context): for UI beyond MirageUi. Call mirage::UseImGui() at the top of each render-thread callback (on_render, on_panel) and draw with ImGui as usual while it returns true.

- `loader/src/core/clock.h`: A real-time clock for measuring the menu itself (scheduler, caches, performance monitor). It can't be QueryPerformanceCounter: during a TAS session the game thread's QPC returns a virtual clock.
- `loader/src/core/compressed_file.h`: zstd-compressed files: logs/.old (log.cpp) and crashlogs/.old (runtime/crash_reporter.cpp) archive earlier sessions' text files with them.

## tools/mirage_tools

- `tools/mirage_tools/__init__.py`: Developer tooling for Mirage (`uv run mirage --help`).
- `tools/mirage_tools/build.py`: Configure, build and test through the CMake presets, with MSVC diagnostics shown as they come in.
- `tools/mirage_tools/cli.py`: `mirage`: one command for building, testing, installing and packaging the project.
- `tools/mirage_tools/devmode.py`: Developer mode: set the environment variable MIRAGE_DEV=1 (or true/yes/on).
- `tools/mirage_tools/devtest.py`: What `mirage dev-test` needs besides building and launching: watching the game, and reporting how the run went (the menu's log, Windows' crash record, the crash location resolved through the PDB, the crash dump).
- `tools/mirage_tools/diaginfo.py`: `mirage --copy-info`: everything needed to diagnose a problem, as one plain-text report on the clipboard.
- `tools/mirage_tools/example_mods.py`: The example Mirage mods (examples/mods): build them the way a mod author would, outside the menu's build.
- `tools/mirage_tools/features.py`: Feature toggles: which modules go into Mirage.dll (the options declared in cmake/Features.cmake).
- `tools/mirage_tools/game.py`: Talking to the game side: the installer (needs admin rights) and the launcher.
- `tools/mirage_tools/gametest.py`: `mirage game-test`: run the menu's in-game self-test (loader/src/selftest.cpp) in the real game and report the result.
- `tools/mirage_tools/hangmon.py`: Hang manager for `mirage game-test`: notices when the game stops making progress, finds out why, records it and ends the game, instead of waiting out the whole timeout (or for someone to press the failsafe).
- `tools/mirage_tools/interactive.py`: Interactive menu: what `mirage` (or `python mirage.py`) does when it is run without arguments.
- `tools/mirage_tools/locks.py`: Which processes have a file open (Windows Restart Manager; no admin rights needed). Used to explain LNK1168 ("cannot open Mirage.dll for writing").
- `tools/mirage_tools/modtools.py`: Tooling for mod authors (step 3 of the plan's next ten steps): a new mod from a template, and a mod checked, built, packaged and installed into the game the same way whatever it is written in.
- `tools/mirage_tools/stagetest.py`: `mirage verbose-build`: build the staged build one stage at a time and test every stage without the game.
- `tools/mirage_tools/toolchain.py`: Finding the 32-bit toolchain, CMake and Ninja.
